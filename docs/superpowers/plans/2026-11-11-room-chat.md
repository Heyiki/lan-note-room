# Temporary Room Chat Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task in the current workspace. No Git repository is present; do not create a worktree or commit.

**Goal:** Replace shared text editing with temporary group chat.

**Architecture:** Keep the native Node HTTP server and vanilla JS frontend.
Room members own stable nicknames. Ordered in-memory messages are posted via
HTTP and replayed/broadcast over ticket-authenticated SSE.

**Tech Stack:** Node.js built-ins, JavaScript modules, Vite, CSS.

**Spec:** `docs/superpowers/specs/2026-11-11-room-chat-design.md`

## Global Constraints

- No additional framework, database or runtime dependency.
- Preserve password authentication, room expiration and idle cleanup.
- Plain text only; 2,000 characters/message and latest 1,000 messages/room.
- Keep unrelated behavior unchanged.

## Task 1: Chat Protocol

Files: `test/chat.test.js`, `server/index.js`, `package.json`.

Interfaces:
- Create/join return `{ room, token, member: { id, nickname } }`.
- GET room returns `{ room, member, messages }`.
- POST messages consumes `{ content, clientId }`, returns `{ message }`.
- A message is `{ id, memberId, nickname, content, createdAt, clientId }`.
- GET events accepts `after` and a single-use ticket, emits `message` with SSE ID.
- Retrying the same member/clientId returns the original retained message.
