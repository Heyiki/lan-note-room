# LAN Note Room

局域网临时群聊。成员加入时自动获得随机昵称，通过 HTTP 发送独立消息，
Node.js 使用 SSE（Server-Sent Events，服务端事件流）实时推送。

## 环境与启动

Node.js 20 或更高版本，支持 Windows / Linux / macOS。

```bash
npm install
npm run build
npm start
```

默认监听 `0.0.0.0:8181`。本机打开 `http://localhost:8181`，
局域网设备使用 `http://运行服务电脑的局域网IP:8181`。
修改项目根目录的 `.env` 即可调整监听地址，`npm start` 和 `npm run dev` 共用：

```dotenv
PORT=8181
HOST=0.0.0.0
MAX_ENCRYPTED_MEMBERS=100
MAX_PLAIN_MEMBERS=100
```

`PORT` 必须为 1～65535 的整数，配置错误时启动会明确报错。
系统环境变量优先于 `.env`；文件缺失时仍默认 `0.0.0.0:8181`。
`.env` 已加入 `.gitignore`，仓库保留 `.env.example` 作为配置示例。
修改配置后需手动重启服务，不会自动切换端口；端口占用时启动失败，不会改用其他端口。

`MAX_ENCRYPTED_MEMBERS` / `MAX_PLAIN_MEMBERS` 分别控制每个加密 / 普通房间的人数上限，
均默认 100，仅接受 JavaScript 安全整数范围内的正整数，配置无效时拒绝启动。
人数包含创建者、待审核申请和离线但未主动退出的成员，同一身份刷新或重复连接不重复占位。
达到上限后拒绝发放新成员令牌，返回 409；主动退出释放名额。
系统环境变量同样优先于 `.env`，Vite 仅使用其中的监听地址，不使用人数设置。

**人数配置不是压力上限或性能保证。** 实际承载取决于服务端及客户端设备、网络、
消息长度/频率、集中入退群和离线补齐量；即使人数未满，也可能发生延迟、同步冲突或资源不足。
提高上限前应在实际部署设备、网络与消息负载下压测，加密房间另受下述累计协议日志容量限制。
修改人数配置需要重启服务，当前内存中的房间会随之清空。

修改前端后重新执行 `npm run build` 并刷新浏览器即可；修改服务端需要重启服务。
`npm run dev` 仅启动 Vite 前端，不包含 API/SSE 服务或代理，不适合直接验证完整群聊。
本项目建议使用构建后的 Node 服务进行联调。

## 功能与规则

- 亮暗主题：首次打开默认暗色，顶栏可切换亮/暗，选择保存在浏览器中。
- 创建房间：随机 96 位房间 ID，密码选填；默认勾选“端到端加密（MLS）”和“入群需批准”。
  加密、密码与审批独立配置；取消加密则创建普通群聊，取消审批则允许自动入群。
  房间创建后不能切换加密模式或审批设置。
- 加入房间：密码正确后发放访问令牌，保存在当前标签页的 `sessionStorage`。
  开启审批时，有无密码都需要现有正式成员批准；待审核用户不能收发消息、批准他人或销毁房间，
  但可以主动退出。关闭审批时，有密码则验证后自动加入，无密码则持房间链接自动加入。
- 随机昵称：使用“形容词＋的＋水果或动物”，例如“悠闲的小熊”“开心的草莓”。
  服务端为创建者及新成员分配房间内唯一昵称，刷新页面后保持身份。
  同一房间不重复使用已分配的昵称；768 种组合全部用尽后才加数字后缀。
  主动退出会清除本标签页的令牌，再加入会获得新身份；不提供自定义昵称或账号。
- 群名右侧实时显示在线人数，按保持 SSE 连接的成员身份去重，包含自己。
  关闭页面或主动退出后更新；断网在服务端检测到连接断开后更新。
  当前页面断线时显示“在线人数未知”。在线人数不影响主动退出销毁规则。
- 群聊消息：纯文本，每条最多 2,000 个 JavaScript 字符串长度单位，
  保留换行；Enter 发送、Shift+Enter 换行，中文输入法确认不会触发发送。
- 消息输入框可上下拖动调整高度，最小 1 行、最大 5 行；超过可视高度后内部滚动。
- 消息显示发送者及时间，自己和他人的消息分列两侧。
- 普通房间保留最近 1,000 条消息，完成入群的新成员可以查看保留的历史；
  待审核用户无法通过房间读取、SSE 历史或实时广播读取消息。
- MLS 房间开启审批时，需要现有在线成员点击“批准加入”；关闭审批时，由在线成员浏览器自动完成加密入群。
  无论是否设置密码、是否需要人工审批，MLS 入群都需要现有成员在线处理 Welcome。
  新成员不能解密加入前的历史；房间内可展开查看自己、其他成员和申请者的身份指纹。
  指纹未自动核验，需通过可信渠道相互比较，随机昵称不等于可信身份。
  自动入群使用约 8 秒的可续期协调租约，减少多个浏览器竞争同一申请；
  协调成员退出时释放租约，断线或无响应时由其他在线成员在超时后接替，不增加额外权限。
- MLS 消息在浏览器内加密、解密，服务端仅保存聊天密文及公开协议元数据。
  成员主动退出后，剩余在线成员自动提交移除更新；更新完成前暂停发送。
  剩余成员都离线时，等待有人重新上线处理。关闭标签页仍不算退出。
- 浏览器使用 IndexedDB 保存 MLS 私钥状态、待确认密文和本地解密历史，以支持刷新恢复。
  这不是本地存储加密；同一浏览器配置中的本地访问者可能读取这些数据。
  同一加密身份不允许在两个标签页同时操作；正常刷新会快速交接本地会话，
  页面崩溃等无法正常交接的情况仍需等待占用期结束（最多约 10 秒）。
  租约、密钥快照和消息历史分开存储，心跳仅更新租约；
  一次补齐的消息、游标和密钥状态以同一事务保存，提交成功后才显示新消息。
  发送前仍先持久化密文与待确认操作；旧版 IndexedDB 记录在取得会话后自动迁移。
  本地密钥丢失时须退出并重新申请加入，不会从服务端恢复密钥或降级成明文。
- 加密及普通房间默认最多 100 名成员（各自由 `.env` 配置，包含待审核及离线未退出成员）。
  MLS 房间保留最近 1,000 条应用密文；
  必要的协议更新保留到房间销毁，协议日志最多 10,000 项、累计载荷最多约 20 MB。
  达到容量后拒绝新操作，需新建房间；离线过久导致所需密文被清理时须重新入群。
- SSE 断开后重新申请一次性连接凭证，按上次收到的消息 ID 补齐保留范围内的消息。
  消息按递增 ID 排序，HTTP 返回及 SSE 推送不会造成重复显示。
- 发送失败时保留当前输入，使用相同发送标识重试不会重复创建仍在历史中的消息。
  尚未发送的输入仅在页面内保留，刷新或退出页面不会保存草稿。
- 已打开的房间正常过期时保留页面上的消息和未发送输入以便复制，停止发送及重连；
  这不会恢复已经从服务端清空的数据。
- 在底部时自动跟随新消息；查看较早消息时提供“查看新消息”按钮。
- 后台标签页收到他人的实时消息时，标题显示未读数量；切回标签页或退出房间后清零。
  自己发送、历史加载、断线补齐和重复消息不计入。
- “退出房间”旁的 👻 按钮悬停提示“有内鬼，终止交易”。任意正式成员点击后立即销毁房间，
  无二次确认，清空服务端消息，在线成员清空聊天页面并返回首页，显示通知“有内鬼，终止交易”；
  断网成员重连后无法继续访问。待审核用户的按钮禁用，直接请求销毁接口也会被拒绝；
  MLS 申请者在完成协议入群前同样没有销毁权限。
- 房间有效期可自定义为 1～1440 分钟（最多 24 小时），默认 60 分钟。
- 最后一名成员点击“退出房间”并成功提交后，立即销毁房间及消息。
  退出会撤销该成员的令牌、未使用的连接凭证并关闭其 SSE 连接。
  刷新、关闭页面、返回首页或断网不算主动退出，不会触发销毁。
  已取消闲置 30 分钟清理；未主动退出的成员仍算在房间中，
  即使全部关闭页面，房间也会保留到固定有效期或服务停止。
- 服务端消息、成员身份、令牌均保存在内存中，服务退出或房间销毁后清空。
  在线浏览器在退出、销毁或发现失效时清理本地房间数据；离线设备不能远程擦除。
  已知到期的本地记录会在下次打开应用时清理，已复制或保存的内容不受影响。

## 接口概览

| 接口 | 用途 |
| --- | --- |
| `POST /api/rooms` | 创建房间，返回房间、成员身份及令牌 |
| `POST /api/rooms/:id/join` | 验证密码并分配新成员 |
| `POST /api/rooms/:id/approve` | 普通房间正式成员批准 `{ memberId }`，重复批准幂等；MLS 房间使用协议接口 |
| `POST /api/rooms/:id/leave` | 撤销当前成员，返回 `{ destroyed }`；最后一人退出时销毁房间 |
| `POST /api/rooms/:id/destroy` | 正式成员立即销毁房间，待审核者返回 403 |
| `GET /api/rooms/:id` | 获取房间、当前成员、`admitted` 状态、可审批的 `pending` 列表及有权读取的消息 |
| `POST /api/rooms/:id/messages` | 发送 `{ content, clientId }` |
| `GET /api/rooms/:id/mls?after=协议序号&rosterVersion=已知成员版本` | 加密状态、增量日志和发生变化时的成员列表 |
| `POST /api/rooms/:id/mls` | 注册公开身份资料，或提交密文、审批及移除更新 |
| `POST /api/rooms/:id/events-ticket` | 申请有效期 30 秒的一次性 SSE 凭证 |
| `GET /api/rooms/:id/events?ticket=...&after=消息ID` | 补齐历史并接收实时消息 |
| `GET /health` | 服务健康状态及房间数量 |

房间读取、发送及凭证申请需要 `Authorization: Bearer <token>`。
创建接口可传 `encrypted: true` 启用 MLS；为兼容旧客户端，省略时创建普通房间。
页面始终明确传递复选框的值。加密房间拒绝普通明文消息接口。
创建接口的 `approvalRequired` 默认 `true`，传 `false` 关闭人工审批，与密码和加密模式无关。
两个选项均只接受布尔值。普通房间使用 `admission-update` 通知浏览器重新获取入群状态和申请列表，
连接建立时也发送一次，避免遗漏连接前的审核变化。
MLS 提交携带 `version` 与 `operationId`；应用消息另外携带 `epoch`，在成员密钥状态不变时
允许不同发送者并发提交，由服务端分配递增流水号，不因其他应用消息占用版本而冲突。
成员变更仍严格匹配当前 `version`，过期 epoch、成员变更冲突或退出处理中返回 409。
已接受操作可幂等重试；客户端按日志顺序处理自己的确认，不跳过其他发送者的消息。
`{ coordinate: true }` 向协议接口申请自动入群协调租约，只有正式成员可申请；
自动入群提交包含 `coordinated: true`，服务端再次检查租约有效性。人工审批不依赖该租约。
Welcome 仅向目标成员提供；待审批成员无法读取群组消息日志。
创建接口的 `ttlHours` 为数值，范围为 `1/60` 至 `24`；页面按分钟填写并换算为小时。
消息包含 `id`、`memberId`、`nickname`、`content`、`createdAt`、`clientId`。
发送者身份由服务端根据令牌决定，不接受客户端指定昵称。
`clientId` 由客户端生成，为 8 至 64 位字母、数字、下划线或连字符。
消息 ID 在房间内递增，历史被清理后不会重置编号。
SSE 历史补齐结束后发送 `sync-complete`，后续 `message` 为实时消息；
`room-destroyed` 表示成员主动终止整个房间，与正常过期的 `room-expired` 区分。
加密房间使用 `mls-update` 通知浏览器按本地持久化游标同步协议日志，
不通过普通 `message` 事件传输聊天正文。
浏览器合并同时到达的同步通知，最多一个同步任务在途，期间的新通知触发后续增量同步；
服务端按流水号直接截取事件后缀，成员列表仅在 `rosterVersion` 变化时返回。
房间信息中的 `onlineCount` 为当前在线人数；
SSE 连接建立、断开及成员退出时，向本房间推送 `presence` 事件 `{ onlineCount }`。

## 验证

```bash
npm test
npm run build
```

测试使用 Node.js 内置测试框架，自动在独立本机端口启动服务，
覆盖昵称及身份保持、密码和令牌、消息排序及历史、输入校验、发送重试、
SSE 广播和断线补齐、一次性凭证、历史容量、主动退出销毁、在线人数及主题偏好。
另包含 MLS 中继审批、版本冲突、幂等提交和退出阻断测试。
Rust 密码适配器测试使用 `npm run test:mls`；
重建 WASM 使用 `npm run build:mls`，普通前端构建不需要 Rust。
依赖版本、重建和独立 HTTP 浏览器验证步骤见 [MLS 说明](mls-prototype/README.md)。

额外的真实 Chrome 验证（需安装 Playwright；也可在命令末尾传入其模块目录）：

```bash
node mls-prototype/verify-storage.mjs
node mls-prototype/verify-app.mjs
node mls-prototype/verify-scale.mjs
```

以上脚本均使用随机临时端口，结束后关闭自己的服务和浏览器，不操作常驻服务。
`verify-storage` 覆盖 v1 数据迁移、原子回滚、独占租约、历史容量和清理；
`verify-app` 覆盖真实页面、SSE、刷新恢复、丢确认、并发发送及协调者超时接替。
`verify-scale` 在一个浏览器页面中运行 100 个独立 MLS 会话，使用真实 WASM、IndexedDB 和 HTTP 中继，
验证入群、100 条并发消息的完整收发、同步通知合并和第 101 人拒绝。
该脚本主动调用同步，不模拟 100 条 SSE 连接或 100 台设备。
2026-11-11 的一次本机运行中，100 个身份建立及入群约 15.1 秒，并发发送和全部接收约 4.7 秒；
100 次重复同步通知合并为 2 次拉取，12 条补齐消息使用 1 次快照保存。
这些是单机功能验证数据，不是吞吐率、目标设备延迟或稳定承载 100 人的承诺。

## 安全边界

- 房间密码使用 scrypt 哈希，不保存明文密码。
- 密码验证依赖服务端，自动入群也信任服务端提供的申请；不防恶意服务端主动插入新成员。
  无密码且关闭审批时，任何持房间链接者都能加入并读取入群后的消息。
- 普通房间的消息以明文存于服务内存；MLS 房间的聊天正文端到端加密。
- 当前 MLS 实现使用 OpenMLS，属于首次集成，未经过独立密码安全审计。
  已在桌面 Chrome 的真实局域网 HTTP 环境验证，手机尺寸模拟不等于所有手机浏览器兼容。
- 默认 HTTP 无传输层保护：即使启用 MLS，房间名称、昵称、成员关系、
  流量时间和大小、房间密码提交及访问令牌仍可能被网络观察者获取。
  HTTP 页面代码被篡改也可窃取明文和密钥，本实现按约定不覆盖这一风险；仍建议配置 HTTPS。
- MLS 成员变更采用标准的签名公开提交；聊天正文始终为加密的应用消息。
  端到端加密不能防止合法成员泄露内容，也不能防止成员或中继拒绝服务。
  私钥泄露后的恢复依赖端点恢复安全并发生后续有效密钥更新，不提供持续受控设备保护。
- 没有发送限速、账号、管理员、成员踢出或权限分级，不适合直接暴露公网。
- 不支持文件、私聊、撤回或消息编辑。
- 房间销毁不会撤回其他设备已经显示、复制或保存的消息。
